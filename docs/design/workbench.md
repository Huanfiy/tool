# 工作室要素约束

适用页面：`studio.html`。本文件记录工作室设计与修改必须遵循的要素约束；转角桌与手办以实拍照片为参考依据。

工作室整体风格见 [设计系统中的工作室风格定位](design-system.md)。场景尺寸、镜头参数、开窗角度、具体窗景素材与渲染技术可按效果调整，但应满足以下约束。

## 空间与物件

| 编号 | 要素 | 设计约束 |
| --- | --- | --- |
| 1 | 地板 | 地板范围与房间比例协调，不向镜头方向延伸大段地板；前方保留活动空间。 |
| 2 | 台灯 | 不设台灯。 |
| 3 | 转角桌 | 参考实际的 L 形转角桌结构：只有靠墙的一侧设置支撑腿，桌前和内侧活动区域保持通畅，避免增加中间或前侧的绊脚支腿。 |
| 4 | 小抽屉柜 | 工作室不设置小抽屉柜，包括桌下的抽屉柜。 |
| 5 | 左侧打印机 | 左侧地面放 3D 打印机，不放落地花盆。打印机直接落地，不设置支撑小桌、推车或独立台架；它是带烟色半透明侧板与门板、实心背板和顶板的封闭落地机，不是裸框架；门板不写深度、不阻挡拾取，底座保留小状态屏。 |
| 6 | 中央椅子 | 房间中央不放椅子，活动空间保持空敞。 |
| 7 | 中央显示器 | 中央显示屏尺寸大、近乎无边框，允许均匀的极窄实体收边，不采用厚边框、宽下巴或重复描边。显示屏本身直接承载可操作的电脑桌面，具体交互见下节。 |
| 8 | 窗户与户外 | 窗户可以实际打开、关闭，窗扇有对应的姿态变化。窗外采用动漫风格的奇幻田园风景，开窗后能够看到连续的户外空间。场景需要表现阳光、分层山丘、树木、花草和飞鸟，并用微风让云、树冠、花草和飞鸟产生持续但舒缓的动态。 |
| 9 | 右侧架子 | 右侧架子陈列 **3 个动漫手办**，不放工具箱；保留实拍参考中的左右顺序、主要配色和姿态特征。 |
| 10 | 右侧电脑主机 | 主机置于工作台最右端附近，但与桌腿、斜撑和横梁保持清晰间距；任何视角下都不应出现主机穿入桌架或桌腿穿入机箱的情况。 |
| 11 | 左上书架 | 书架与书本采用可辨认的立体结构：每本书由两块封板、内缩且带页缘纹理的书页块、圆角书脊和凸起书脊带组成；书脊标题按中文竖排逐字直立，拉丁字母段落转向竖读。书底落在架面上、彼此贴靠，末端一本靠在书列上斜倚，不得悬空或沉入架面。固定陈列至少包括《刻意练习》《我们为什么要睡觉》《foc 原理》，可搭配嵌入式、控制与信号类书籍。垂吊盆栽放在书列右侧的空余架面，花盆与藤蔓不得与任何书本相交，藤蔓从盆沿越出后垂在架前。 |
| 12 | 挂板工具 | 工具采用彼此可辨认的立体轮廓和部件，不使用同一简模重复代替。固定包含剪刀、螺丝刀、斜口钳、小刀和万用表；万用表包含屏幕、拨盘、插孔及表笔等主要特征。螺丝刀为细长带握纹的柄加颈环和长杆；小刀为刀刃朝下、露出斜切刀尖的美工刀，不得读作手机或打火机。 |
| 17 | 开发板 | 开发板为架在铜柱上的绿色 PCB：铜走线、过孔、焊盘与丝印绘制在板面纹理上，走线只允许正交与 45° 折线且不得穿过元件；芯片为四边鹅翼引脚落在焊盘上的 LQFP，排针为双排，另有 USB-C、稳压器、晶振、电解电容、复位/启动按键、状态与电源 LED 和插在排母上的 OLED 模块。展开电路板时板面保留元件焊盘与丝印轮廓。 |
| 15 | 圆角与描边 | `box()` 的直角 ink 线只用于圆角半径小于 .04 的盒体；更大圆角（示波器、焊台等）只保留轮廓壳，避免描边漂离壳体形成第二轮廓。 |
| 16 | 室内光照与日夜 | 夜间照明来自左右两条架下灯带各一盏暖色点光加窗侧冷色月光，不设台灯，不允许单点强光在墙面形成热点。首屏日夜跟随主站 `localStorage.theme`；没有记忆时按本地时间（18:00–06:00 为夜）；页内切换写回同一键。 |
| 13 | 挂钟 | 墙面不挂时钟；界面和电脑系统内的时间显示不受此约束。 |
| 14 | 鼠标 | 桌面不放鼠标、触控板及其专用线缆；显示器仍须支持直接指针与触控交互。 |
| 18 | 桌上小精灵 | 工作台右端、笔记本与主机之间的空余桌面（约 x 3.5）放一只手掌大小的程序化小精灵：圆头圆身、奶白肚皮、头顶小芽、身边三粒缓慢环绕的灵气。它落在显示器屏幕宽度之外，不遮挡屏幕，也不占据鼠标的常规位置。点击或轻触会让它小跳一下，并在头顶弹出一条便签风气泡短句；不进入设备面板、不推近镜头、不参与"带我逛逛"。造型（`js/studio-spirit.js`）、气泡（`js/studio-spirit-bubble.js`）与语料（`js/studio-spirit-speech.js`）三者相互独立：语料按时间、日夜、窗与设备状态选句，接入 AI 时只替换 speech provider，密钥与网络请求不得进入前端。 |

## 窗外景观与动效

- 窗外是奇幻田园风格，不使用“工作室位于山顶”的高山照片质感。远景应以低矮分层田野、树木、草地、花朵和小型生活痕迹构成。
- 阳光应在天空和室内光照中可见；云层缓慢漂移，飞鸟有飞行和振翅，树冠、草叶与花朵随微风摆动。关闭窗户时，窗扇合拢但户外景观仍可见，风的动效减弱。
- 草采用长短错落、向外弯曲并逐渐收尖的薄叶簇，不使用直立尖锥或交叉硬片堆成“竹笋”。以柔和嫩绿、根叶渐变和不均匀的小片群落营造动漫自然感；草仅在石径远离工作室的一侧稀疏保留，石径到外墙之间（包括靠房路边和窗下）不生成草，风动时叶片也不得伸入。保留空地并避开石径、树干，不铺满写实密草；花朵不随草丛清除。
- 景观使用本地代码或资源，不依赖运行时图片服务；从背面或极端俯仰角观察时不能露出方形画板、空白边缘或山顶悬崖感。
- 房屋属于户外环境：景观与窗户是同级对象，以实体墙、窗框和窗扇的正常深度遮挡形成窗口。没有实体遮挡的户外，不得按窗洞投影或相机位于墙哪一侧裁掉；不得误删用于 HTML 显示器的透明孔洞。
- 外墙脚与室内地面接近同层，窄石边处理建筑厚度，庭院以缓坡连接中景与低成本远地表。前后转角也要接地，精细网格边界不能成为土地的终点。
- 房子四周保留同层的院子带：地表纸色淡出是"庭院椭圆 ∪ 环绕房屋轮廓的圆角矩形"，房屋右侧与开敞正面至少有约 3.5 个单位的草地色再收束为纸面，低角度看房子不能像漂在纸上。石径从左前角分出一小段通向房前；院子外缘以低矮绿篱和小片花丛点缀，绿篱位于淡出带边缘、不遮挡概览中的墙脚。
- 闭合远景覆盖全部允许镜头及过渡，但田园细节集中在窗向；其余方位、地表外缘与天空外围以宽幅、世界固定的主题色过渡承接纸面留白。远丘保留可辨认的分层对比，中景有低矮树丛衔接近处果园与远处画布；远景小屋不落在 overview 页头区。不能用满屏高饱和色带、加浓全局雾、跟随相机移动背景或收紧镜头来掩盖边界。
- 修改镜头目标、角度、缩放范围或背景位置后，必须重算相机可达范围、背景半径和远裁剪面；地表收口与背景覆盖分开验收。草木及云鸟完整运动范围要避开相机可达区域，窗扇整个开合扫掠范围须留空。
- 镜头预设的构图约束：小实验（robotics）从房内前侧看向侧桌，打印机不入画、外墙截面不入镜，电机台—机械臂—焊台/示波器一字排开、窗景作背景；打印角（fabrication）从开敞正面看向打印机，以窗墙内面与侧桌为背景，庭院只在墙端外留窄带；开发板设备视角取较陡的近距俯视，显示器只作为顶部一条。所有预设的方位角、俯仰角与距离必须落在 OrbitControls 当前限制内，不得依赖夹取。
- 拾取与可见遮挡一致：天空不参与拾取，实体土地、树干和树冠能挡住设备点击，但不能误触开关窗。显示器被实体遮住时，原生点击和滚动同样不能穿透。
- 户外云鸟和风动不能使全场阴影持续刷新。静态远景不周期重绘或上传；相同主题、相同质量档位的重复调用不分配新纹理。减少动态时固定户外时间，主题和窗扇仍可操作。

## 显示屏的直接交互

显示器应像房间里真实可用的电脑一样工作，终端、相册和 Robot 均在这块屏幕内操作。

- 屏幕支持直接点击、文字输入、选择和滚动，不需要先靠近，再点击“进入 huanfly-os”。未靠近时，点击屏幕主体任意可见位置（含应用控件）都会触发靠近，同一次点击仍交给应用处理；已靠近时不重复触发。靠近在完成点击时触发，不拦截应用的输入、文字选择、拖动和滚动；实体遮挡检查仍然生效。
- 靠近、退后只改变镜头与屏幕的视觉大小，屏幕内容始终贴合显示器所在平面，不通过独立弹层或替代桌面完成切换。靠近完成时，镜头位于实际屏幕中心的法线上并正对屏幕，不保留俯视或侧视；环视角度限制不得将正对目的位置重新夹成俯视。
- 镜头变化保留应用状态，包括终端内容、相册浏览位置和聊天草稿，避免重新打开或重置应用。
- 屏幕内的输入、拖动与滚动由应用处理，避免误触发房间环视或镜头缩放；屏幕外保留场景操作。
- HTML 桌面与 WebGL 透明孔洞共用尺寸、平面与镜头；极窄实体边缘从屏幕尺寸派生，显示器外壳不叠加膨胀描边。HTML 只向边缘下方延伸深色底，消除双重抗锯齿的浅色接缝，不放大桌面内容或原生点击范围。
- 屏幕应有自发光观感：清晰的深色底、克制的发光边缘与附近桌面的冷色补光；靠近时不让全屏纸纹罩住显示内容，不以泛白反光或全局亮度滤镜牺牲文字、照片的对比度。装饰不拦截输入，不增加动态阴影或后处理通道。
- 靠近屏幕时，底部视角条、标签与设备清单随简介、日志一起淡出并不可聚焦，只保留页头与"退后看看"；不让房间导航叠在键盘上。
- 相册预览在同一物理屏幕内完整等比显示图片，横图、竖图和长图均允许留白但不裁切，不要求上下滚动看完整图片。返回、切图和说明独立占位；紧凑布局优先留足看图高度，保留返回后的相册位置。相册不超过 4 张时按大幅照片排版，不用稀疏缩略图。

上述显示器与相册行为由 `tests/studio-apps-browser.cjs` 回归；真机检查项见 [工作室真机验收](../todo/studio-real-device-acceptance.md)。

## 终端与 Robot 的能力边界

- 终端一律为浏览器内的访客模拟，不连接访客电脑或服务器，不提供管理员终端、真实 shell、PTY、终端 WebSocket 或命令执行接口。模拟命令只能展示虚拟内容、打开预设站内页面及操控场景里的模拟设备。
- Robot 目前只保留同一物理显示器内的入口与「研究中」静态占位，不提供聊天、配置、模拟回复、网络调用或聊天存储；不另开页面、弹层或服务。
- 通用 Server 研究计划已移出工作区，git 历史 `2d9c4e7` 可查。未来恢复研究须重新确认范围，不得自动重建后端；密钥仍不得进入前端、Git 或静态产物。

## 后续修改

调整布局、替换资产或改造交互时，对照上述 18 项约束检查：不得引入绊脚桌腿、超长地板、挂钟、鼠标、台灯、抽屉柜或电脑二次进入流程；窗外不得是山顶照片，房子不得漂在纯纸面上。新的用户要求覆盖旧约束时，同步更新本文件。
